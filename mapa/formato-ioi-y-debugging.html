🧭 Formato IOI y cómo debuggear con agilidad

Guía para entender cómo se entregan y prueban las tareas de la IOI. Relacionado: Interactivos · Longest Trip · volver a Temas.

📦 El “archivo adjunto” de cada tarea

Junto al enunciado, cada problema trae un .zip adjunto con el material para trabajar en tu propia máquina. Ejemplo (Longest Trip, IOI 2023):

cpp/
├── <problema>.h        # interfaz: qué función implementas y cuáles puedes llamar
├── <problema>.cpp      # stub: el esqueleto vacío que completas
├── grader.cpp          # grader de ejemplo: simula al juez localmente
├── compile_cpp.sh      # compila tu código + el grader
└── run_cpp.sh          # ejecuta con los límites de memoria/stack del juez
examples/
├── 01.in / 01.out      # caso de ejemplo (entrada y salida esperada)
└── 02.in / 02.out

El adjunto del concurso son solo esos archivos. Las carpetas solutions/ y graders/ (manager + testlib) que ves en el repo vienen del paquete oficial completo que se publica después de la competencia — oro para entrenar, pero no se entrega durante el concurso.

🔌 Tareas con grader (interactivas / por funciones)

Muchas tareas IOI no usan cin/cout. En vez de leer datos, implementas una función y, si es interactiva, haces preguntas llamando a funciones que el grader te provee. Ejemplo (longesttrip.h):

El grader de ejemplo (grader.cpp):

  • lee el caso de la entrada (ej. el grafo como matriz de adyacencia),
  • responde tus llamadas y te vigila: arreglos válidos/disjuntos, y sobre todo un límite de llamadas (pasarte = 0 puntos),
  • imprime tu salida y cuántas llamadas usaste.

⚠️ El grader de ejemplo normalmente no verifica que tu respuesta sea correcta (eso lo hace el checker oficial, oculto). Localmente debes verificarla tú — ver el mini-ejercicio.

Reglas de oro (errores típicos de principiante)

  1. Nunca imprimas debug a stdout en una tarea con grader: ahí va el protocolo y lo romperías. Usa std::cerr (fprintf(stderr, ...)).
  2. Cuenta tus llamadas: el grader te dice cuántas usaste. Correcto pero pasado de presupuesto = 0 puntos.
  3. Compila con warnings (-Wall -Wextra) y prueba con el caso chico (para entender) y el grande (para tiempo/límites).
  4. Aísla el bug: reduce el caso, agrega assert, y compara una solución que falla (solutions/incorrect/) contra una correcta (solutions/correct/).
  5. Estrategia de subtareas: lee TODOS los subtasks primero. A veces la subtarea 1 se resuelve con 3 líneas (ej. en Longest Trip, con densidad D=3 el grafo es completo y cualquier orden es un viaje válido).
