📖 La lección

Cómo es una competencia

En una olimpiada (OCI, IOI) recibes unos pocos problemas y varias horas. Cada problema vale 100 puntos repartidos en subtareas: versiones más fáciles del problema (con límites más chicos) que valen puntos parciales. Esto define la estrategia central de toda la ruta: asegurar subtareas vale más que perseguir la solución perfecta. Una fuerza bruta correcta puede valer 30–50 puntos.

Cada subtarea es, en la práctica, un problema distinto con su propio límite: la primera se gana con la idea más simple que exista, la última exige la solución eficiente. Por eso se leen todas antes de programar.

Anatomía de un enunciado

Un enunciado describe una situación, una tarea, la entrada, la salida y los límites. La historia puede contener condiciones esenciales: tradúcelas a operaciones, sin saltártelas.

Ejemplo: entradas para un festival. Se venden n entradas a p pesos cada una. Se pide el dinero recaudado.

ParteQué diceQué deducimos
Entradados enteros n y phay dos datos, no una lista de compradores
Restricciones0 ≤ n ≤ 10⁹, 1 ≤ p ≤ 10⁶repetir n veces puede ser demasiado trabajo
Tareacalcular la recaudaciónsumar p n veces o multiplicar n por p
Salidaun enterocon 3 2000, imprimir 6000

La suma repetida usa n operaciones; el producto hace una cantidad constante. Pero elegir la fórmula no resuelve el rango: el máximo es 10¹⁵, de modo que hay que multiplicar en long long. Rapidez y representación son dos decisiones distintas.

Las restricciones son tu brújula

Una referencia aproximada es 10⁸ operaciones simples por segundo, pero depende del equipo, las constantes, la memoria y las operaciones. Estos órdenes de magnitud ayudan a descartar enfoques; no garantizan que una solución pase:

n máximoPuedes permitirteEjemplo
n ≤ 202ⁿprobar todos los subconjuntos
n ≤ 500n³triple ciclo
n ≤ 5 000n²doble ciclo
n ≤ 200 000n log nordenar, búsqueda binaria
n ≤ 10⁷nun solo recorrido

Las dos líneas de sync_with_stdio/cin.tie aceleran la lectura — inclúyelas siempre; en entradas grandes marcan la diferencia entre pasar y TLE. El while (t--) es la forma corta de “repetir t veces”: la condición usa el valor de t y de paso le resta 1, hasta que llega a 0.

El enemigo silencioso: overflow

Un int aguanta hasta ~2·10⁹. Multiplica dos números de un millón y…

La primera multiplicación se desborda con int de 32 bits: en C++ el desbordamiento de enteros con signo tiene comportamiento indefinido, así que no hay una salida garantizada. Guardar después en long long no lo repara: la multiplicación ya ocurrió entre ints. La segunda expresión sí se calcula en 64 bits y vale 1000000000000.

El dibujo muestra el rango representable. No asigna un resultado a una operación que desborda.

Desliza el diagrama para verlo completo.

Regla práctica de competencia: si los valores pueden superar 10⁹, trabaja en long long de punta a punta. Y el reflejo que salva partidas: cuando un resultado que debería ser positivo aparece negativo o absurdamente chico, la primera sospecha es overflow.

Los veredictos del juez

AC aceptado · WA respuesta incorrecta · TLE se pasó del tiempo · RTE el programa se cayó (índice fuera de rango, división por cero) · CE no compiló. Son pistas, no diagnósticos exclusivos: un acceso inválido también puede causar WA, y un ciclo infinito puede causar TLE. Como punto de partida, mira WA → lógica o caso borde; TLE → complejidad; RTE → índices y límites.

Del enunciado a una solución

  1. Lee la tarea y las restricciones (¿qué n? ¿qué cabe?).
  2. Piensa un ejemplo chico a mano antes de programar.
  3. Elige el enfoque que quepa en la tabla de arriba.
  4. Programa, prueba con los ejemplos y un caso borde propio.
  5. Envía. Si falla, el veredicto te dice dónde buscar.

Práctica directa: Elegir tipo y trabajo

Lee n y p con 0≤n≤10⁹, 1≤p≤10⁶; imprime n·p. Entrada: 1000000000 1000000. Salida: 1000000000000000.

Idea para comprobar tu solución

Un producto evita repetir mil millones de sumas, pero debe hacerse en long long desde el principio.

Un ejemplo para pensar

Un problema pide la suma de n números de hasta un millón. Una subtarea permite n ≤ 100; la completa, n ≤ 200 000. Una solución recorre los números una sola vez y acumula en un int de 32 bits. ¿Basta con que sea rápida?

Tiempo y rango son preguntas distintas

El recorrido hace como máximo 200 000 sumas, pero el resultado puede llegar a 200 000 000 000. La subtarea pequeña cabe en int; la completa exige un tipo de mayor rango, como long long. Un algoritmo puede tener una complejidad adecuada y aun así representar mal su respuesta. El tipo del acumulador se elige con la suma máxima, no con el tamaño de cada número por separado.
